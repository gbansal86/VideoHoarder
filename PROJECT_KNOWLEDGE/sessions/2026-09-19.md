# Session Handoff — 2026-09-19

## Objective

Implement the first no-layout-change download improvements: actual simultaneous full-download videos, bounded per-video fragment downloading, correctly scoped cancellation/process ownership, and per-video job logging.

## Completed

- Separated generic queue workers (`workflow_workers`) from video concurrency (`parallel_videos`).
- Rebound the existing **Simultaneous downloads** spinner to `parallel_videos` without changing page layout.
- Replaced the serial full-download row loop with a bounded 1-5 thread executor while preserving result order.
- Propagated the parent `JobContext` into executor threads so stop/cancel and subprocess ownership remain job-scoped.
- Added durable `video_scheduler_started`, `video_started`, `video_finished`, and `video_exception` log events containing video identity.
- Added bounded yt-dlp `--concurrent-fragments` arguments (1-16, default 4) through a centralized argv-list helper.
- Added safe integer fallback/bounds and configuration validation/defaults.
- Extended bounded parallelism to metadata source expansion/details, media-only URL batches, external-media URL batches, and the legacy download stage.
- Added per-video active transfer state (`percent`, `speed`, `ETA`, stage) and aggregate parent transfer percent.
- Made `VLM_VIDEO_LIBRARY` override saved path configuration.
- Enabled UTF-8/replacement-safe Windows stdout/stderr at startup.
- Changed disabled transcript/chapter/report validation rows from misleading `FAIL` to `NOT REQUESTED`.
- Added a live-refreshing child-video table to the existing Job Details panel with video title, status, progress, speed, and ETA.
- Cancellation now immediately marks unfinished child rows `CANCELLING`, terminally records cancelled work, and stops yt-dlp fallback strategies instead of trying all clients after a stop.
- Added an all-videos/per-video event filter and live log viewer beneath the child table.
- Throttled parallel terminal progress into readable VIDEO_ID-labelled lines.
